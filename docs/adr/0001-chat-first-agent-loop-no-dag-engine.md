# 聊天优先 + 工具调用，不建 DAG 流程引擎

客服助手的架构形态定为：LLM tool-use agent loop 是核心，查询和操作都是工具，确定性环节（退款分级、额度判定）写成普通代码。我们考虑过混合方案（对话走 loop、退款分级跑独立流程引擎）和流程优先方案（全流程 DAG 化，参考 AutoGPT graph 引擎），都因为引入一套需要长期维护的引擎而被否决——客服的"流程"本质上是模型选定的工具调用序列，领域规则由代码守门（额度、审批、转人工是一等控制原语），比把流程固化成 DAG 更贴合领域模型。AutoGPT graph 引擎的可借鉴物是其中的机制（状态落库、HITL 暂停恢复、原子输入合并），不是引擎本身。

## Consequences

- 不需要工作流定义、节点编排、DAG 校验这些子系统
- 退款分级等"确定性"要求由代码层工具包装保证，模型无法绕过
- 若未来出现真正需要编排的复杂流程，再评估引入，而不是预先建设
