# PostgreSQL + pgvector，单库承载关系数据与向量

数据与向量检索都用 PostgreSQL（向量列 `vector(1536)`，余弦检索），不引入独立向量库。客服知识库（FAQ、商品、售后政策）的规模和召回要求初期用不了专用向量库的生态优势，而"一个库管所有状态"直接支撑了本项目的核心设计——会话、审批、循环状态全部落库可恢复（ADR-0002），跨库一致性是不必要的复杂度。参考 AutoGPT：UnifiedContentEmbedding 统一嵌入表 + ContentType 枚举扩展 + 原生 SQL 余弦查询，直接照搬建模。若未来召回质量或规模成为瓶颈，迁移成本集中在嵌入表一张表，可逆。

## Consequences

- 文档切片、召回评估需要自建（AutoGPT 只有嵌入表和查询函数）
- 嵌入模型换型需要重灌向量列，模型选型要趁早定
